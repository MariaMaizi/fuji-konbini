## 在自己的电脑上运行

### 1. 准备运行环境

安装 Node.js 22 或更新版本。这份副本已使用 Node.js 24.19.0 做过检查。后端只使用 Node 内置模块，浏览器库已放在 `web/vendor/`，运行此版本不需要先安装项目依赖。

在包含 `package.json` 的项目文件夹打开终端：

```powershell
npm start
```

随后打开 http://127.0.0.1:8011/ 。只看场景、搜索商品和使用浏览功能时，不需要填写模型密钥。

### 2. 如果端口已被原项目占用

在新终端设置另一个端口，然后启动：

```powershell
$env:PORT='8014'
npm start
```

打开 http://127.0.0.1:8014/ 。当前终端中按 Ctrl+C 可以停止这次运行。

### 3. 如果需要体验模型对话

将 `server/.env.example` 复制为 `server/.env.bailian`，在自己的电脑里填写 `DASHSCOPE_API_KEY`，随后重启后端。

示例选择 `CLERK_PROVIDER=bailian`、`BAILIAN_MODEL=qwen3.6-plus`、`CLERK_REPLY_MODE=direct`。使用者需要在模型服务商处自行获得可用的密钥与模型权限；费用和额度以自己的账户设置为准。本仓库不附带密钥或免费额度，也没有配置自动备用模型。

私有配置保存在静态网页目录之外。不要把真实密钥放入 `web/`、提交记录或聊天截图中。更细的环境变量与配置说明见 [后端说明](../server/README.md)。

## 可以体验哪些内容

进入便利店后，以第一人称行走、浏览分类、搜索商品，把单品或整组搭配加入购物篮，并通过 Find 在店内寻找商品。

店员面板支持中、日、英对话，固定操作界面使用英文，包装与招牌保留日文。当前 3D 店员属于简化原型，聊天也可能出现错误属性或卡片不一致；这些是后续迭代内容。

## 怎样检查一次修改

```sh
npm run check
npm test
```

第一条检查目录 ID、图片、模型节点与网页文件依赖。第二条运行现有离线测试，包含当前路径和保留的结构化实验逻辑，用模拟响应完成接口检查，不发真实模型请求。

测试通过说明相应代码检查通过，不表示模型在任意自然语言输入下都能给出准确建议。文字和素材说明的更新，只需检查对应文档、图片和链接，不必反复运行全部模型接口测试。

## 文件、素材与维护

代码、模型导出、网页素材、正交参考图和文档分别放在 `web/`、`server/`、`design/`、`docs/` 中。可编辑 Blender 源工程和历史建模备份另存在本地，当前仓库包含网页运行所需的模型导出。

商品价格、食品资料与模型身份分开记录。更换图片时应核对商品 ID 和包装对应关系，不能仅按颜色接近而替换成另一款商品。正交参考图展示设计过程，网页商品标签用于商品卡片，两者分开维护。

每天完成一个实际改进后，可以检查、提交并推送变更。文件位置与命令示例见 [日常更新指南](daily-updates.zh-CN.md)。
